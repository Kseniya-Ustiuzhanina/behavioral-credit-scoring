# Поведенческий скоринг: прогноз просрочки 90+ дней

Модель оценивает вероятность того, что у действующего заёмщика в течение 12 месяцев возникнет просрочка от 90 дней. Прогноз строится по истории клиента на дату скоринга: транзакции по MCC-категориям, кредитный рейтинг, параметры кредита, наличие ипотеки, макропоказатели.

**Стек:** Python, pandas, scikit-learn, imbalanced-learn, Optuna, mlxtend

## Бизнес-задача

Заявочный скоринг оценивает клиента только в момент выдачи кредита. Поведенческий скоринг нужен, чтобы заранее видеть ухудшение платёжного поведения уже действующих заёмщиков.

Решение принимается по порогу на откалиброванной вероятности. Порог должен одновременно выполнить три требования:

| Метрика | Требование |
|---|---|
| Approval rate — доля одобренных | ≥ 65% |
| Default rate — доля дефолтов среди одобренных | ≤ 2% |
| Missed defaults rate — доля пропущенных дефолтов | ≤ 4% |

## Данные

8 таблиц, 13 500 клиентов, 2013–2019 годы. Итоговая таблица — 438 379 наблюдений «клиент × месяц», доля дефолтов 11,3%.

Данные учебные (Яндекс Практикум) и в репозиторий не входят. Для запуска положите CSV-файлы в папку `data/`:

```
ds_15_loan_payment_credit.csv    ds_15_client_description.csv
ds_15_transactions.csv           ds_15_credit_description.csv
ds_15_mortgage_presence.csv      ds_15_credit_rating.csv
ds_15_macro_data.csv             ds_15_cohort_grid.csv
```

## Подход

- **Без утечки из будущего.** Признаки считаются только по завершённым месяцам до даты скоринга. Рейтинг и макропоказатели берутся с лагом.
- **Признаки поведения:** средние траты по MCC за 3 месяца, динамика трат (3 месяца к предыдущим 3), доли обязательных и необязательных расходов, срок отношений с банком, изменение рейтинга.
- **Неполный горизонт.** Для дат после 2018 года будущие дефолты ещё не видны (у декабря 2019 доля дефолтов 1,1% вместо 10–11%), поэтому они исключены из выборки.
- **Разбиение по времени:** обучение 2013–2016, калибровка 2017, тест 2018. Кросс-валидация — `GroupTimeSeriesSplit` по календарным годам.
- **Модели:** логистическая регрессия и случайный лес, без балансировки и с ней (`class_weight`, RandomOverSampler, SMOTE, RandomUnderSampler). Лучшая — RandomForest + RandomUnderSampler.
- **Подбор гиперпараметров:** Optuna. Целевая функция — missed defaults rate при пороге, который фиксирует approval rate на 65%.
- **Калибровка:** изотоническая, на отдельной выборке 2017 года.

## Результаты

| | Калибровка (2017) | Тест (2018) |
|---|---|---|
| ROC-AUC | 0,908 | 0,908 |
| Approval rate | 65,1% ✅ | 70,8% ✅ |
| Default rate | 0,50% ✅ | 1,01% ✅ |
| Missed defaults rate | 3,22% ✅ | 6,48% ❌ |

- Калибровка снизила Brier score с 0,107 до 0,066 и выровняла среднюю предсказанную вероятность с фактической долей дефолтов.
- Ранжирующая способность на тесте не упала, ROC-AUC тот же. Но в 2018 году доля дефолтов выросла с 10,1% до 11,1%. Калибровка 2017 года стала занижать риск, и при том же пороге модель пропустила вдвое больше дефолтов.
- Вывод для внедрения: порог и калибровку нужно регулярно пересматривать, хотя бы раз в квартал или раз в год.
- Самый важный признак — срок отношений с банком (~43%), но его вклад отчасти артефакт выборки: история клиента обрывается на дефолте. Второй — динамика трат: падение расходов сигнализирует о риске сильнее, чем их абсолютный уровень.
